## packages/ui/src/components/skeleton/skeleton.behavior.ts (new)

Checked against container.behavior.ts and grid.behavior.ts (the two static
precedents on this branch). Container's `aria` projection is empty (`{}`
-- landmarks are native to the element); grid's is real and non-trivial
(conditional role, aria-label, data-preset/data-columns). Skeleton's is
real but the simplest possible case: `{ 'aria-hidden': 'true' }`,
unconditional, no config/state branching. No duplicate logic with
container/grid -- the shape (name/parts/initialState/actions/canDispatch/
aria/keymap/effects) is the BehaviorSpec contract every score fills, not
shared substance between components (boundary 3 is about framework files
sharing lines beyond the adapter; behavior files are the thing being
scored, not the adapter). No abstraction invented: nine-value
`SkeletonVariant` union mirrors the oracle 1:1, no enum machinery added.
Nothing stringly-typed beyond the literal union type itself, which is the
established pattern (compare `ButtonVariant`, `ContainerElement`).

## packages/ui/src/components/skeleton/skeleton.classes.ts (new)

Checked against button.classes.ts and container.classes.ts for the
selection-among-literals shape (Spec 00 boundary 6). No `resolveFillName`/
fill-resolver import: I considered routing `variant` through the generic
`fill` primitive (container's pattern) but resolveFillName's grammar has
no "-subtle" stop -- `fill="primary"` resolves to solid `bg-primary` +
paired `text-primary-foreground`, which is not what a skeleton wants (loud
solid surface, and a foreground class with no text to color). The matrix's
pre-existing stub for skeleton already declared `uses.current: ["classy"]`
only (no fill-resolver), corroborating that this component was scoped to
stay off the fill primitive. Kept the oracle's literal `bg-*-subtle`
map instead -- same shape as `variantClasses` in button.classes.ts, just a
different literal set. No foreground pairing at all (unlike button, whose
text sits on a SOLID surface) -- checked this against the
contrast-pairing defect class flagged in the task (bg-*-subtle mismatched
against solid *-foreground, as in the old alert oracle): skeleton renders
no text node at all, so the correct fix here is "emit no foreground class,"
not "emit the right one." No duplication with button's variant map --
different literal values, different color-vocabulary tier (subtle vs.
solid), no shared string to hoist.
